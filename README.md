## Что здесь

Проект мониторит участок подписки ПРАЙМ — обращения в поддержку (`support_tickets`), сегмент «кэшбэк», окно апрель–сентябрь 2025. Считает операционные метрики нагрузки на поддержку: количество тикетов, долю решённых, время закрытия обращения, раскладку по дням недели и пиковые дни. Показывает паспорт участка, активность клиентов и динамику накопления нагрузки внутри окна; дополнительно оценивает достоверность выборки из 1000 участников и сравнивает сегмент между собой.

## Как запустить

Нужны [Git](https://git-scm.com/) и [uv](https://docs.astral.sh/uv/).
Python отдельно ставить не нужно — его поставит uv.

```bash
git clone git@github.com:ВАШ_ЛОГИН/prime-monitor.git
cd prime-monitor
uv sync
```

Доступ к учебной базе выдаёт бот курса по команде `/db`. Полученную строку
подключения кладём в `.env`:

```bash
cp .env.example .env
# и вписать в .env строку из бота
```

Проверка, что всё встало:

```bash
uv run python -c "from prime.config import get_engine; print(get_engine().connect().execute(__import__('sqlalchemy').text('select current_user')).scalar())"
```

Запуск JupyterLab:

```bash
uv run jupyter lab
```

## Что здесь считается

---| Метрика | Определение | На каких данных |
|---|---|---|
| Паспорт участка | Всего строк; строк с `ok = True` (решённых); сумма `value` по решённым (часы работы поддержки); число уникальных дней | `rows` — выгрузка 1000 клиентов сегмента «кэшбэк» за 01.04.2025–30.09.2025 |
| Доля несостоявшихся | `(всего строк − ok=True) / всего строк` | `rows` |
| Участники с обоими исходами | Число `actor_id`, у которых есть хотя бы одна строка с `ok = True` и хотя бы одна с `ok = False` | `rows` |
| Сумма value по дням недели | Сумма `value` по строкам с `ok = True`, сгруппированная по `weekday()` | `rows`, только решённые тикеты |
| Самый активный участник | `actor_id` с наибольшим числом строк `ok = True`; при ничьей — минимальный `actor_id` лексикографически | `rows`, только решённые тикеты |
| Топ-3 пиковых дня | Три даты с наибольшей суммой `value` по `ok = True`; при равенстве сумм — раньше идёт более ранняя дата | `rows`, только решённые тикеты |
| День накопления половины суммы | Порядковый номер дня (в списке дней с хотя бы одним `ok = True`), на котором накопленная сумма `value` впервые достигает половины общей суммы | `rows`, только решённые тикеты |
| Взвешенная сумма по дням недели | Сумма `value` по дням недели, умноженная на коэффициент из справочника `WEIGHTS` (Mon=1.00, Tue=1.05, Wed=1.05, Thu=1.00, Fri=0.95); для отсутствующих в справочнике дней — коэффициент 1.0 | `rows`, только решённые тикеты |
| Value на участника (исследование А) | Сумма `value` по `ok = True`, делённая на `count(distinct actor_id)` | SQL-агрегат по всей таблице `support_tickets` за окно |
| Доля решённых `ok_share` (исследование А, Б) | `avg(case when ok then 1.0 else 0.0 end)` | SQL-агрегат по таблице за окно |
| Строк на участника (исследование Б) | `count(*) / count(distinct actor_id)` | SQL-агрегат по таблице за окно |
| Value на одну решённую строку (исследование Б) | Сумма `value` по `ok = True`, делённая на число строк с `ok = True` | SQL-агрегат по таблице за окно |
| Главный драйвер различий между сегментами (исследование Б) | Множитель с наибольшим коэффициентом вариации (CV = stdev / mean) среди трёх: `rows_per_actor`, `ok_share`, `value_per_ok_row` | SQL-агрегат с `group by segment` по таблице за окно |
